User guide

PBIP Lineage Explorer

See where every number on a Power BI report comes from, and what would be affected if you changed it. This guide covers how to open a project, read the screens, and get answers to the questions people ask most.

1. What it does

When a Power BI report is saved as a PBIP project (a folder of text files rather than one .pbix), the Lineage Explorer can read that folder and show you how everything connects:

  • Visual → measure → column → source. Click any chart and trace its numbers back through the DAX measures to the table columns and, finally, to the database table and column they came from, even if a column was renamed in Power Query.
  • Change impact. Pick a measure and see every other measure that depends on it and every visual, page, and report that would be affected by changing it.
  • Unused measures and columns. Find what nothing uses, graded by how safely it could be removed.
  • Recent changes. If the project is in git, see what changed in recent commits and which visuals that touched.

It only readsThe tool never edits your Power BI files, never connects to a database, and never sends anything off your computer. Think of it as an X-ray, not a scalpel.

2. Getting started

What you need

  • Chrome or Edge. The tool uses a browser feature for reading folders that Firefox and Safari do not fully support.
  • A PBIP project folder. In Power BI Desktop: File → Save as, choose the .pbip type. You get a folder containing a Name.Report folder and a Name.SemanticModel folder. If you have several reports that share one model, save them all into the same parent folder.
  • Node.js, installed once, if you run the tool from your own PC with the launcher. If someone has hosted the tool on an internal web address for you, skip this.

Starting the tool on your PC

  1. Open the tool's folder and double-click start.bat (Windows) or start.command (Mac).
  2. The first run installs a few components and takes a couple of minutes. After that it starts in seconds.
  3. Your browser opens at http://localhost:5173. Leave the black console window open while you use the tool; closing it stops the local server.

Opening a project

  1. Click Open Project Folder.
  2. Pick the folder that contains the .Report and .SemanticModel folders. To analyse several reports together, pick the parent folder that holds all of them. If more than one report is found and they use different models, the tool asks which to load.
  3. The browser may ask "Let site view files?" Choose View files. This permission is for viewing only.
  4. Wait a few seconds while the project is read. The sidebar fills with measures and visuals.

No project handy? Click Try Sample Project on the welcome screen to explore a small built-in example. You can also drag a project folder onto the welcome screen.

3. Around the screen

Toolbar (top)

Project totals, and buttons for Measure Map, Health, Source Map, Export All, and keyboard help (?).

Measures tab (left)

Every DAX measure, grouped by table. Type to search by name or formula. Badges show a measure's status (see section 5). Tick True orphans only to see measures nothing uses.

Visuals tab (left)

Every visual, grouped by page (and by report when several are loaded). Hover a page's Layout button for a thumbnail; click it to see where each visual sits on the page.

Dependents tab (left)

A spreadsheet-style grid, one row per measure, with counts of what it depends on, what depends on it, and how many visuals, pages, reports, and filters it reaches. Click a column header to sort; export to CSV.

Main panel

Shows whatever you selected: an interactive tree diagram, a Dependencies strip, the DAX chain, the source-column table, and recent changes.

Measure Map

Full-screen map with one measure in the middle. Pick a measure from the list on the left or click one in the map to re-centre.

4. Common tasks

"Where does this chart get its numbers?"

Trace a visual back to its source columns.

  1. Open the Visuals tab and click the visual (search by its title or type if the list is long).
  2. The tree shows Visual → Measures → Tables/Columns → Power Query → Source. Scroll or drag to pan; use the + / − buttons or scroll wheel to zoom; click a node to collapse its branch.
  3. Below the tree, the Source Columns section lists every source table and column feeding the visual, with any renames shown as source name → Power BI name.
  4. Use Grouped by Source to see which databases and tables are involved at a glance.

"What breaks if I change this measure?"

See the full blast radius of a measure.

  1. Open the Measures tab and click the measure.
  2. Read the Dependencies strip: four side-by-side lists of the visuals it reaches (with report and page), the measures that depend on it, the measures it uses, and the columns it uses.
  3. For the picture version, click Measure Map in the toolbar (or the Map button next to the measure). The measure sits in the middle; everything that depends on it fans out to the right, ending at the visuals, labelled by report and page.
  4. Click any other measure in the map to re-centre on it and follow the chain.

"Which measures can we clean up?"

Find unused measures and columns safely.

  1. Click Health in the toolbar. The orphan lists are split by how disconnected each measure is: True Orphans (safest to remove), Visual Orphans (investigate), Filter / Security Orphans (usually keep), and Field / Column Orphans.
  2. Or in the Measures tab, tick True orphans only.
  3. Before deleting anything, read section 5. The tool only knows about the reports you loaded.

"Which database tables feed this report?"

Get the full column-to-source mapping as a table.

  1. Click Source Map in the toolbar.
  2. Search or sort the table of every Power BI column with its original source column, source table, database, and server.
  3. Click Export CSV to hand the list to a data engineer or paste it into documentation.

"How do all our measures relate to each other?"

Compare every measure at once.

  1. Open the Dependents tab. Each row is one measure with its dependency counts and status.
  2. Sort by Dependents to find the measures most other calculations rely on (the riskiest to change), or by Visuals to find the most displayed.
  3. Click a row to open that measure. Use the export button for a CSV.

"What changed recently?"

Review commit-by-commit changes (git projects only).

  1. Open a project folder that is a git repository. After loading, the toolbar shows a "Scanning git history" note, then a count of commits and changes.
  2. Measures and pages with recent changes get a numbered badge in the sidebar. Click a badge to see what changed and which visuals it affects.
  3. When a measure is selected, a Recent Changes section appears below its lineage.

Exporting and sharing

  • Export All (toolbar): one CSV with every measure, its columns, and source mapping.
  • Tree diagram: export buttons above the tree save it as SVG or PNG.
  • Impact panel (the ↗ Impact button on a measure): export a Markdown report of what depends on it.
  • Links: the address bar updates as you click (for example #measure=…). Copy it to send a colleague straight to the same measure; they need the same project loaded.

5. Measure status and orphans

Every measure gets one of four statuses. The tool works them out by following each measure forward through everything that uses it and checking what it finally reaches: a visual, an active filter, a security rule, or nothing.

In useno badge

Shown on at least one visual, directly or through another measure. Nothing to do.

Filter / RLSblue badge

Not shown on any visual, but it is actively filtering a visual, page, or report, or it is part of a row-level-security rule that controls who sees what. It is doing real work. Usually keep.

No visualamber badge

Other measures reference it, but none of them end up on a visual either. It is wired in, but nothing shows the result. Worth investigating: either the whole chain is unused or something was disconnected by accident.

True orphanred badge · "orphan"

Nothing references it at all: no visual, no measure, no filter, no security rule. Safest to remove, after the check below.

When people say "orphan" without qualifying it, they usually mean a True Orphan. The toolbar's orphan count adds up all three non-green statuses; the Health page splits them apart.

Filters: set vs. just sitting there

A field in the filter pane only counts as "in use" if the filter actually has a value applied (items ticked, a "greater than", a Top N, a relative date). A field parked in the pane with (All) selected is not filtering anything and is ignored, because the report would look the same without it.

Unused columns

The Health page also lists columns that nothing references. These are listed separately from measures because the fix is different: an unused column costs memory and refresh time; an unused measure just clutters the model.

Before you deleteThe tool only sees the files you loaded. A measure used by another report you did not load, by an Excel connection, by a paginated report, or by another team's model will still show as an orphan here. Treat the lists as "nothing in these files uses this", and confirm with the report owners before removing anything.

7. Privacy and license, briefly

Your files stay on your computer

The tool runs entirely inside your browser tab. It reads the folder you choose (view only), works in memory, and sends nothing anywhere. There is no login, no server, no tracking. Close the tab and the data is gone.

It never changes anything

It cannot edit Power BI files and does not connect to databases. The only files it creates are the exports you ask for.

Handle exports with care

Exports and screenshots contain table names, formulas, and connection details (server and database names). Treat them like any internal design document.

Free to use

Open-source under the MIT license. It can be used, copied, and modified freely for internal work, with no cost and no obligation beyond keeping the license notice with the code. It comes with no warranty, so use its results as a guide, not as gospel.

8. FAQ

"Open Project Folder" does nothing or shows an error.

Make sure you are in Chrome or Edge and the address starts with http://localhost or https://. The folder picker does not work when the page is opened straight from a file share. Some managed browsers block the folder picker; if so, ask your IT team.

Measures show "Load SemanticModel Folder" and no source columns.

You opened a .Report folder on its own. Click Load SemanticModel Folder in the banner and pick the matching .SemanticModel folder, or re-open the parent folder that contains both.

A measure I know is used shows as an orphan.

Most often the report that uses it was not loaded. Open the parent folder containing all related reports. If it is used only in a filter, check that the filter has a value applied; an unset filter does not count. See section 5.

The tree is huge and hard to read.

Click nodes to collapse branches you do not need, use Fit to zoom to the whole tree, or switch to the Measure Map for a flatter view centred on one measure. Export to SVG for a zoomable image.

The change history says "No recent changes" or does not appear.

The folder must be a git repository (contain a .git folder) with commits that touched the PBIP files. The tool reads only local history; it does not fetch from a remote.

Can I share a view with a colleague?

Copy the address bar link after selecting something. Your colleague opens the tool, loads the same project folder, and the link jumps to the same selection.

Does it work without internet?

Yes. Once the page is open, nothing needs a connection.

9. Glossary

PBIPPower BI Project. A report saved as a folder of text files instead of one .pbix.
Semantic modelThe data side of a report: tables, columns, measures, relationships, security rules, and the queries that load data.
ReportThe visual side: pages, charts, slicers, filters.
MeasureA named DAX calculation, such as Total Sales. Measures can use other measures.
DAXThe formula language measures are written in.
VisualAny chart, card, table, or slicer on a page.
Filter paneThe panel where fields can be added to filter a visual, a page, or the whole report.
RLSRow-level security: rules that limit which rows each user can see.
Field parameterA dropdown that lets a reader swap which measure a visual shows.
Power QueryThe step that loads and shapes data before it reaches the model; where columns are often renamed.
LineageThe chain from a number on screen back to the source column it came from.
True orphanA measure that nothing in the loaded files references at all.
